🔐 What is ECH？

ECH（Encrypted Client Hello，encrypted client hello) is TLS a new feature used to encrypts the domain info that would otherwise be exposed in plaintext。

If you want more complete, technical details, see Cloudflare Official blog:
👉 https://blog.cloudflare.com/zh-cn/announcing-encrypted-client-hello/

📖 Background

When we use WS + TLS when proxying through that node:

  • ✅ The actual communication content has been TLS encrypted; the GFW cannot see the specific content you visit
  • ❌ but in TLS handshake stage still exposes one key piece of information:SNI

SNI is the node's camouflage domain (HOST)

That is to say:

GFW Although it cannot see what you visit, it knows you are"circumvention"，and knows which domain you are connecting to.

⚠️ what problems does it bring?

this is why anomalies often occur in the following scenarios:

  • ❌ v2rayN Batch test real-link latency
  • ❌ Clash policy groups auto-select nodes

usually manifests as:

all nodes instantly -1，All unusable

the cause is not that the node really failed, but Carrier / GFW disrupt proxy connections by blocking access to node domains。
since this blocking is mostly automated policy and prone to false positives, after a while the node may work again，loop repeatedly.

💡 ECH role of

ECH core role is:

will SNI（i.e. the node domain) encrypted

Enable ECH from:

  • ✅ GFW Cannot get the real node domain
  • ✅ The externally observed domain will uniformly show as:cloudflare-ech.com

this, at the root, blocks the ability to precisely censor nodes by domain。

🤔 ECH Will it get blocked?

In theory, the GFW only need directly blocked cloudflare-ech.com That's it.

But this will:

  • ❌ collateral damage to many normal users ECH websites and services
  • ❌ brings high blocking costs and side effects

Therefore,ECH how long it lasts depends on GFW trade-offs and strategies，is still very effective at this stage.

⚠️ Close TLSTransport-layer encryption

🔒 You are about to close Shadowsocks of TLS transport encryption. To avoid losing the node, first confirm your deployment environment meets the requirements.

☁️ Close TLS first, confirm these three points:
  1. The project must be deployed on Workers（is not Pages）。
  2. in Cloudflare turn off in “always use HTTPS”
    SSL/TLS > Edge certificate > always use HTTPS > Close
    or HOST Use directly *.workers.dev domain assigned by the project.
  3. the preferred IP/domain used by Port must be HTTP type ports, e.g.: 80、8080、8880、2052、2082、2086、2095。

📘 Transport and encryption notes

📡 Close TLS afterwards data will HTTP transmitted in plaintext, no longer has TLSEncrypt link encapsulation and camouflage capability.

🔐 but the node is still by Shadowsocks AEAD（aes-128-gcm / aes-256-gcm）encrypted; the traffic data itself is still transmitted encrypted.

✅ Summary: the final traffic will in plaintext Transport encrypt data。
