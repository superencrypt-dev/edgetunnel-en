🔐 What is ECH？

ECH（Encrypted Client Hello, encrypted ClientHello) is a new TLS feature for Encrypt domain information that would otherwise be exposed in plain text。

If you want a more complete, technical explanation, please refer to Cloudflare Official blog:
👉 https://blog.cloudflare.com/zh-cn/announcing-encrypted-client-hello/

📖 Background notes

When we use WS + TLS When proxying through nodes of:

  • ✅ Actual communication content has been TLS Encrypt,GFW Cannot see the specific content you visit
  • ❌ But in TLS During the handshake, one key piece of information is still exposed:SNI

SNI is the node's disguised domain (HOST）

That is:

GFW Although we don't know what you are visiting, we know you are"Bypass firewall", and knows which domain you are connecting to.

⚠️ What problems will it cause?

This is why anomalies often occur in the following scenarios:

  • ❌ v2rayN Batch test real link latency
  • ❌ Clash Policy group auto-selects nodes

Usually appears as:

All nodes instantly -1, all unavailable

The reason is not that the node actually failed, but rather Carrier / GFW Disrupt Proxy connections by blocking access to node domains。
Since such blocking is mostly automated policy and prone to false positives, ... Nodes may recover after some time, repeat loop.

💡 ECH Function of

ECH Core function is:

encrypts SNI (i.e. the node domain)

After enabling ECH:

  • ✅ GFW Unable to fetch the real node domain
  • ✅ Externally observed domains will all be shown as:cloudflare-ech.com

This fundamentally This blocks precise blocking of nodes by domain name。

🤔 ECH Will it be blocked?

Theoretically,GFW Just Block directly cloudflare-ech.com That's all.

But this will:

  • ❌ False positives hurting normal usage ECH Websites and services
  • ❌ Brings higher blocking costs and side effects

Therefore,ECH How long it lasts depends on GFW Trade-offs and strategies for, still very effective at least at the current stage.

☁️ Close TLS Before, please confirm the following three points:
  1. Project must be deployed on Workers(Not Pages）。
  2. In Cloudflare, disable “Always use HTTPS”
    SSL/TLS > Edge certificate > Always use HTTPS > Close
    or HOST - use directly *.workers.dev Domain assigned by the project.
  3. Preferred in useIP/of the domain Port Must be HTTP Type port, e.g.: 80、8080、8880、2052、2082、2086、2095。

📘 Transfer and encryption description

📡 Close TLS Afterwards, data will HTTP Transmitted in plaintext, no longer provides TLSEncrypt Encapsulation and disguise capability for the link.

🔐 But nodes are still managed by... Shadowsocks AEAD（aes-128-gcm / aes-256-gcm) encryption, traffic data itself is still transmitted encrypted.

✅ Summary: final traffic will In plain text Transfer Encrypted data。
